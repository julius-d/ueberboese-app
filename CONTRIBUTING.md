# Contributing

Contributions are more than welcome :)

## Code contributions

Before opening a pull request, please open an issue explaining the changes you want to make.

## Local set up
This project uses flutter to create an Android app, a Mac app and a Linux app and potentially in the future also an iOS app.

### Flutter version
The Flutter version is pinned in `.fvmrc` and managed with [FVM](https://fvm.app). Install it once with:
```shell
fvm install
```
On Windows, FVM creates symlinks. This requires Developer Mode (Settings → System → For developers) or an elevated shell.

Then prefix commands with `fvm` (e.g. `fvm flutter run`, `fvm dart format`). FVM links the pinned SDK to `.fvm/flutter_sdk`, which stays valid when the version changes. Point your IDE to that path; the Dart extension for VS Code usually detects it automatically.

### Generated mocks
The test mocks (`*.mocks.dart`) are generated by `build_runner` and are not committed. Generate them after cloning and whenever you add or change `@GenerateMocks` or a mocked class:
```shell
dart run build_runner build --delete-conflicting-outputs
```
During development you can let them regenerate automatically:
```shell
dart run build_runner watch --delete-conflicting-outputs
```

### Android
See https://docs.flutter.dev/platform-integration/android/setup

Start an emulator by name
```shell
flutter emulators --launch Pixel_9
```

To start the app locally run
```shell
flutter run
```

Hot reload: press `r` in the console were you started flutter

## Before you commit

Before you commit your changes always make sure to run:
```shell
dart format lib test
flutter analyze
flutter test
```
CI fails if any file in `lib` or `test` is not formatted. The line width is set in `analysis_options.yaml`, so your IDE settings don't change the result.
